# Online Work Log

This is the K7 implementation of docs/swarm-operator-hour.md, extended with ongoing milestones. Activity is the raw event stream; Work Log is a concise account of concrete accomplishments and remaining work, generated both during long Codex turns and at actual terminal boundaries.

## Ownership and data flow

`WorkLogPanel` owns only its new renderer surface. C7 mounts it below the agent list. Typed `workLog.read/start/stop/record` requests pass through `protocol/work-log.ts` and `core/worker-runtime.ts` to `core/work-log/service.ts`. The renderer cannot supply transcript paths or process commands.

The cockpit-facing panel callbacks are `onOpen(entry)`, `onAgent(sessionId)` and `onTask(taskId)`, with optional `coreGeneration`. Earlier `onOpenAgent`/`onOpenTask` names remain compatible aliases. `WorkLogEntryDetail` is a pure center-pane surface taking `entry`, `onAgent`, `onTask`, and optional `onClose`; it adds no polling, model or mutation authority. C7 retains central selection/layout ownership; sidebar Record remains explicit.

`transcripts.ts` reads only the operator's private registered sessions, at most 512 KiB each. It checks the registered session header, ignores synthetic sessions and partial JSONL records, enforces nested/fork ownership, and extracts bounded assistant/tool evidence. An ongoing milestone requires a matching result for a concrete edit, check/build, Git/PR publication, or explicit Ditz action; prose, invocation alone, read-only inspection, command-looking quoted text and noisy results do not qualify. Result normalization preserves legacy strings and accepts only bounded `input_text` strings from current content-block arrays; image and unknown object blocks are ignored rather than serialized into evidence. Actual `task_complete` remains the only terminal boundary, and `turn_aborted` only advances the private cursor. Initial watching considers evidence from the last 30 minutes, newest four sessions first, not all inherited history. A recent operation in a many-hour turn is eligible by its own evidence time. Inputs are capped at 10,000 characters per session and are model data, not instructions. General private absolute paths and common credential/header forms are scrubbed before inference and persistence; raw transcript files never become repository artifacts. JSONL offsets and line limits use the original bytes, so invalid UTF-8 or oversized multibyte records cannot drift a checkpoint. The first direct real check found ROOT's latest completed turn 280 KiB behind its live tail, which exceeded the initial 128 KiB reader; the bounded window was increased without increasing model input.

`commands.ts` runs one bounded normal authenticated Codex exec owner at a time, default model `gpt-5.6-luna`, with structured output. Settings support the Codex harness and a model name, plus a 10–600 second milestone batching delay. The first concrete operation opens a persisted fixed window; later work joins it without postponing the deadline, and restart retains it. The primary core watches automatically unless the separately persisted Pause preference is set. Stop aborts the owned process group and waits for close. No observed worker is resumed, messaged or killed.

Private Git worktree state remembers one ordered per-session transcript checkpoint before inference: validated file identity, complete-line byte position, anchor, evidence time, bounded owned-turn identity and milestone/terminal/abort kind. That one cursor covers milestone, abort and terminal progress, so the paths cannot replay one another or revive an aborted, nested or already-terminal span. Its saved line anchor rejects replaced, truncated or rewritten input; an open milestone offset remains valid when the bounded tail moves. After a closed checkpoint falls behind that tail, an explicit different terminal turn may bridge the gap, while ambiguous milestone evidence continues to fail closed until a new owned `task_started` is visible. An unchanged or failed paid input is not automatically retried after failure or restart. Kernel locks serialize producer runs across windows, order Pause against final publication, and serialize Ditz note transactions across worktrees. `.swarm/work-log.json` is the human-readable repository artifact: provenance, outcomes, changed areas, checks, follow-ups and session/task links. It retains the latest 200 entries. A model summary never closes an issue or proves a check independently.

Only complete lines after the previous processed byte position are eligible. The saved anchor is re-read directly even after it scrolls outside the finite tail, so later evidence remains eligible without resending the old context. Empty startup turns are ignored; a terminal after a saved milestone remains independently eligible. Normal CLI structured-output behavior follows [Codex non-interactive documentation](https://learn.chatgpt.com/docs/non-interactive-mode).

Explicit Record outcome requires an exact completed Ditz issue. If registration supplied a task ID it must match. Ditz is read, checked for the stable entry marker, and commented while holding the same mutation lock; a repeated request does not duplicate the note. A successful write marks that outcome completed. Owner/ROOT continues to own issue closure and Git commit/sync of generated artifacts.

## Build connections and checks

The implementation is included by `//:quality_sources` in `//:desktop-bundle`. `//tools/work-log:check` runs node/renderer typechecks and dedicated Work Log tests. `//tools/work-log:proof` is an explicit operator-authorized direct producer/Ditz demonstration, never an automatic test model call. Changes to this path must keep this data flow, controls and build mapping accurate.

## Milestone and terminal semantics

New generated rows carry explicit `milestone` or `terminal` provenance. Milestones remain `working` historical accomplishments and the panel labels them **Milestone**; current liveness still comes from the agent-status producer. Terminal rows are completed or failed according to the exact `task_complete` event. Legacy origin-less working rows retain the bounded repair path, while explicit milestones are never relabeled during restart. A final assistant message followed by `turn_aborted` never becomes a completed row.

## Prototype limits

Codex is the only implemented harness. Work Log does not summarize every tool: only a bounded concrete-operation batch or an actual terminal becomes an input. A process failure records an attempted checkpoint and displays a short error rather than auto-retrying paid inference. Input batching and the finite tail can omit older work; this is an operator summary, not an exhaustive audit. User reviews generated notes before explicit Ditz recording. No automatic issue close, commit, push, global transcript scan or deployment authority.
