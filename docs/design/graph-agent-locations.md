# Agent locations on graphs

The **Agents** switch is enabled by default and shows eligible registered agents at their last observed file location. Click a robot to open its exact conversation; it does not also select the underlying node. The tooltip separates execution status, the file operation, latest activity, and the origin worktree and branch. A completed, waiting or failed agent never animates as working; a retained observation is marked “Last seen”. Multiple agents stay independently selectable.

Locations come from the bounded transcript window already displayed in Activity. Relative paths are resolved inside the agent's own canonical origin worktree and then translated to project-relative paths. If a path escapes that worktree, or the relevant event has left the window, no position is displayed. Older context documents and task prose are not substitutes for an observed file event.

The renderer uses the existing registered fleet and selected transcript observation. Core derives an opaque project identity from Git's canonical common directory and publishes a checked branch for each validated registration. Fleet snapshots refresh canonical Git identity in bounded batches so branch transitions conservatively narrow scope. Repeated selected-detail and handoff reads resolve only the selected root, coalesce concurrent discovery, and reuse the latest snapshot identity instead of rescanning every registered root; they never invent fresher branch status. A selected default-branch worktree gets project visibility, admitting other registered worktrees only when they have the same derived identity. Any non-default, detached, unknown, or otherwise uncertain selection stays exact-worktree scoped. An unrelated repository is never admitted by path resemblance or branch name. These fields are additive: older observations parse, but uncertainty narrows scope instead of broadening it.

Eligibility and placement are separate. Every eligible agent remains reachable through the graph layer's compact located/unplaced summary even when there is no trustworthy node mapping. The summary is a bounded, scrollable overlay inside one intentional canvas layer, so an agent-heavy list cannot add an implicit row or collapse a service, plan, task, repository, build, or design canvas. Placed task sprites deliberately escape the task node's clipping boundary while their own event isolation preserves node selection and graph panning. Outside-root, noncanonical, unsupported, or pathless observations are unplaced; their conversation is not discarded and no fallback position is invented. A retained observation may remain at its last valid explicit path and is marked “Last seen”. A file operation is an observed tool request, not proof the operation succeeded. Native runs currently expose generic activity summaries without file paths, so they remain unplaced in this increment.

Each graph retains its own meaning. Repository nodes use the nearest visible file or directory. Build targets use direct observed Bazel source-input links only. Components use authored source paths and document links; authored task IDs also allow exact task membership. Services and interfaces use declared source membership from the same published graph. The task graph accepts only exact current task IDs and current revision-pinned backlink/detail paths, never prose similarity. The component build-mapping projection has no file-to-target membership in its schema, so eligible agents are honestly unplaced there. None of these mappings creates an edge or animated journey. Nodes and edges retain their identities and positions when observations update; the React context overlay changes independently. Mock sprites remain opt-in preview data, not registered activity.

Fresh startup opens the launch workspace through the existing typed `workspace.open` request, so its descriptor supplies the canonical root before an operator has switched worktrees. Repository, build, service, plan hierarchy, component/design, component build-mapping, and task projections all mount the same overlay contract. Core generation, loaded task revision, visible-node, and current-navigation fences prevent retained data from placing sprites after a refresh or workspace switch.

`app/renderer/graph-agents/GraphAgents.tsx`, `locations.ts` and `graph-agents.css` are actual `//:quality_sources` inputs to `//:desktop-bundle`. `//tools/live-sprites:checks` reads that source filegroup and `//tools/live-sprites:sources`; it covers project and exact-worktree scope, unrelated-repository rejection, pathless/unplaced reachability, explicit memberships, exact click identity, keyboard isolation, fresh startup and stable graph arrays/cameras. `//tools/live-sprites:smoke` consumes the packaged desktop and builds its own private registry plus disposable primary, linked-feature, and unrelated repositories inside an owned virtual-desktop directory. Its agent-heavy geometry case proves bounded service and authored-plan overlays plus a fully visible/clickable exact task sprite, alongside multi-worktree repository/service/component placement, exact feature scope, unrelated exclusion, retained source/cameras, and zero model turns without touching a live registry, agent process, or physical display.
