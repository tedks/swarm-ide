# Agent locations on graphs

The **Agents** switch shows registered agents at their last observed file location. Click a robot to open its conversation; it does not also select the underlying node. The tooltip separates execution status, the file operation and the latest activity. A completed, waiting or failed agent never animates as working; a retained observation is marked “Last seen”. Multiple agents stay independently selectable.

Locations come from the bounded transcript window already displayed in Activity. If the last path is outside this worktree, or the relevant file event has left that window, no position is displayed. Older context documents and task prose are not substitutes for an observed file event.

The renderer uses the existing registered fleet and selected transcript observation. A checked canonical worktree must exactly equal the current workspace root. A relative event path is interpreted against its explicit working directory, or the registered root when absent; outside-root, noncanonical and unsupported paths are not placed. An unlocated agent remains in the agent list. A file operation is an observed tool request, not proof the operation succeeded. Native runs currently expose generic activity summaries without file paths, so they have no graph position in this increment. Do not mine summaries, tasks or source attachments to invent that position.

Each graph retains its own meaning. Repository nodes use the nearest visible file or directory. Build targets use direct observed Bazel source-input links only. Components use authored source paths and document links. Services and interfaces use declared source membership from the same published graph. None of these mappings creates an edge or animated journey. Nodes and edges retain their identities and positions when observations update; the React context overlay changes independently. Mock sprites remain opt-in preview data, not registered activity.

Fresh startup opens the launch workspace through the existing typed `workspace.open` request, so its descriptor supplies the canonical root before an operator has switched worktrees. Core generation and current navigation fencing remain unchanged.

`app/renderer/graph-agents/GraphAgents.tsx`, `locations.ts` and `graph-agents.css` are actual `//:quality_sources` inputs to `//:desktop-bundle`. `//tools/live-sprites:checks` reads that source filegroup and `//tools/live-sprites:sources`; it covers worktree mismatch, stale/terminal lifecycle, explicit memberships, exact click identity, keyboard isolation, fresh startup and stable graph arrays/cameras. `//tools/live-sprites:smoke` consumes the desktop bundle plus the owned virtual-desktop and demo-agent helper source groups. It observes an existing private registry without sending messages or modifying agent processes.
